# Subxt 0.50 upgrade — Phase 1 design

**Date**: 2026-04-13
**Scope**: Phase 1 of a two-phase effort. This document covers **only** the subxt 0.50 compatibility upgrade with opportunistic cleanup of fragile code, preserving the current head/finalized-only indexing behavior. Historical block sync is **Phase 2** and will have its own design document.

---

## Context & motivation

Maestro currently uses subxt 0.44. The 0.50 release (paritytech/subxt) brings:
- Support for historical block indexing (back to genesis, with user-provided types for pre-V14 metadata) — enabling a capability the project has been blocked on
- A significant restructuring of the API surface: `PolkadotConfig` becomes builder-based, block selection moves to a "block-first" pattern (`api.at_current_block()` then `.storage()` / `.events()` / `.runtime_apis()`), subscriptions are renamed (`subscribe_finalized()` → `stream_blocks()`), storage access is redesigned around `entry(query).fetch()`, and `subxt-core` is removed (its logic moved to `frame-decode`)
- Automatic metadata versioning (no more runtime update monitoring code to maintain)

The upgrade is required for continued subxt maintenance and is the precondition for historical sync.

## Phase decomposition

| Phase | Scope | Status |
|---|---|---|
| **1** (this doc) | Upgrade to subxt 0.50, preserve head/finalized-only behavior, cleanup of fragile timestamp extraction and SCALE→JSON conversion | **Designed** |
| **2** (future doc) | Historical block sync: new `BlockSource::fetch_block_at()`, backfill loop, `use_historic_types(true)`, CLI for start-block | Not started |

## Non-goals for Phase 1

- Historical block sync (Phase 2)
- Changes to `BlockSource` or `StorageReader` trait signatures
- Changes to `RawBlock` / `RawEvent` / `RawExtrinsic` model shapes
- Changes to `maestro-core::error::ChainError` variants
- Changes to handler interfaces or any consumer of `event.data` / `extrinsic.args` JSON
- Changes to `bin/maestro/src/main.rs` startup flow (aside from whatever bubbles up from API renames)

## Acceptance criteria ("done" gate)

1. `cargo build --release` passes
2. `cargo clippy --all -- -D warnings` passes
3. `cargo test` passes — includes one golden fixture test (balances block) and unit tests for `scale_json.rs`
4. Manual smoke test: `maestro --ws-url <allfeat-node>` indexes ≥ 10 blocks without error
5. Manual smoke test: all three handler bundles (balances, ats, midds) show at least one record written to the database during the smoke run

Points 1–3 are automated. Points 4–5 are manual and must be documented in the PR description.

## 1. Architecture & dependencies

### Workspace dependency changes (`Cargo.toml`)

- `subxt = "0.44"` → `subxt = "0.50"`
- Possibly add: `frame-decode` (where `subxt-core` logic moved in 0.50) — used by `scale_json.rs` / decoder if `field_values()` on events/extrinsics no longer yields a `Composite<T>` directly
- Possibly add: direct `scale-value = "<version matching subxt 0.50 internal>"` if subxt 0.50 no longer re-exports `subxt::ext::scale_value`

No other dependency additions.

### New crate layout (`crates/substrate/src/`)

```
lib.rs            # pub re-exports (public surface unchanged)
client.rs         # SubstrateClient::connect, finalized_head, best_head,
                  # stream_blocks/stream_best_blocks, runtime_version, genesis_hash,
                  # impl BlockSource
storage.rs        # impl StorageReader (read_storage, read_storage_map, read_storage_map_u64)
decode/
  mod.rs          # pub(crate) fn decode_raw_block(client, block) -> ChainResult<RawBlock>
  extrinsics.rs   # decode_extrinsics + get_extrinsic_result
  events.rs       # decode_events
  timestamp.rs    # read_block_timestamp via Timestamp::Now storage
scale_json.rs     # SCALE Value → serde_json::Value with documented invariants
```

### Public surface (unchanged)

`lib.rs` continues to re-export `SubstrateClient` and `SubstrateClientConfig`. No changes in `bin/maestro/src/main.rs` or in other crates. The `BlockSource` trait in `maestro-core` is **strictly identical** in Phase 1; Phase 2 will add `fetch_block_at`.

### Fixed technical choices

- **Backend**: keep the explicit `ChainHeadBackend` (consistent with current intent). If 0.50 deprecates or removes it, fall back to the default backend — to be resolved at first compile.
- **Config**: `PolkadotConfig::builder().use_historic_types(false).build()`. `false` is correct for Phase 1 (head only, current metadata) and is the documented hook Phase 2 will flip to `true`.

## 2. Subxt 0.44 → 0.50 call-site mapping

For each call site in the current adapter, the target 0.50 form. Exact symbol names will be validated against the real crate documentation at implementation time; if any differ from the forms below, the fix is localized (≤5 lines per site). See also Risk R1.

### Connection & client (`client.rs`)

```rust
// Current (0.44)
let backend = ChainHeadBackendBuilder::default()
    .build_with_background_driver(rpc_client.clone());
let client = OnlineClient::<PolkadotConfig>::from_backend(Arc::new(backend)).await?;

// Target (0.50)
let config = PolkadotConfig::builder()
    .use_historic_types(false)   // Phase 2 hook
    .build();
let backend = ChainHeadBackendBuilder::default()
    .build_with_background_driver(rpc_client.clone());
let client = OnlineClient::<PolkadotConfig>::new_with_config_from_backend(
    Arc::new(backend),
    config,
).await?;
```

### Head / genesis / runtime version

```rust
// Current
let head = client.blocks().at_latest().await?;
let number = head.number();
let hash = head.hash();
let version = client.runtime_version();

// Target — block-first pattern
let at_block = client.at_current_block().await?;
let number = at_block.number();
let hash = at_block.hash();
let version = at_block.runtime_version(); // or client.runtime_version() if retained
```

`finalized_head` and `best_head` today both return via `at_latest()` — this is a ChainHead backend shortcut. With 0.50 the same simplification is kept: both return the backend's current head. Finalized vs best is exclusively carried by the stream choice.

### Block streaming

```rust
// Current
let sub = client.blocks().subscribe_finalized().await?;
let sub = client.blocks().subscribe_best().await?;

// Target
let stream = client.stream_blocks().await?;       // finalized equivalent
let stream = client.stream_best_blocks().await?;  // best equivalent
```

The `impl BlockSource::subscribe_finalized/subscribe_best` wrapper keeps its shape: wrap with `.then(|r| async move { decode_raw_block(&client, &block).await })` and box into `FinalizedBlockStream`. Trait unchanged.

### Block events / extrinsics access

```rust
// Current
let events = block.events().await?;
let extrinsics = block.extrinsics().await?;

// Target — via at_block handle from stream yield, or via client.at(hash)
let at_block = /* block yielded by stream_blocks() */;
let events = at_block.events().await?;
let extrinsics = at_block.extrinsics().await?;
```

If the stream yield type does not expose `.events()` / `.extrinsics()` directly, fall back to `client.at(block.hash()).await?` to obtain a uniform handle.

### Storage reads (`storage.rs`)

```rust
// Current (read_storage)
let storage = client.storage().at(hash).fetch_raw(key).await?;

// Target
let at_block = client.at(hash).await?;
let storage = at_block.storage().fetch_raw(key).await?;
```

```rust
// Current (read_storage_map*)
let storage_query = subxt::dynamic::storage(pallet, item, vec![Value::from_bytes(map_key)]);
let address_bytes = client.storage().address_bytes(&storage_query)?;
client.storage().at(hash).fetch_raw(address_bytes).await?;

// Target
let query = subxt::dynamic::storage(pallet, item, vec![Value::from_bytes(map_key)]);
let at_block = client.at(hash).await?;
let entry = at_block.storage().entry(query)?;
let value = entry.fetch().await?; // Option<StorageValue>
let bytes = value.map(|v| v.bytes().to_vec());
```

All three `StorageReader` methods remain byte-for-byte identical in contract: `Option<Vec<u8>>` return with the same "None = missing" semantics. MIDDS bundle (the only consumer) is not touched.

### Errors

In 0.50, different APIs return specific error types, all convertible to `subxt::Error`. Phase 1 does **not** take advantage of the differentiation — we continue to collapse to `subxt::Error` then map to `ChainError::*`. See Section 6.

### What disappears

- `try_decode_compact_u64` + tests (timestamp fallback decoder)
- `parse_timestamp_from_debug` + test
- `get_block_timestamp` (replaced by storage read, see Section 3)
- `composite_to_json`, `value_def_to_json`, `primitive_to_json`, `try_as_byte_array` from `client.rs` (moved to `scale_json.rs` and rewritten, see Section 4)
- Runtime update monitoring code (0.50 handles automatically)

## 3. Timestamp extraction cleanup

### Current (fragile)

`get_block_timestamp` iterates extrinsics, finds `Timestamp.set`, then does `format!("{:?}", values)` and scans the string with a heuristic "a number between 2020 and 2050 in ms". Fallback path manually decodes a `Compact<u64>` from raw SCALE bytes.

### Replacement

Read `Timestamp::Now` directly via storage at the block's hash — the canonical value the runtime writes, no debug-string parsing.

### New module: `crates/substrate/src/decode/timestamp.rs`

```rust
use codec::Decode;
use subxt::{OnlineClient, PolkadotConfig};

use maestro_core::error::{ChainError, ChainResult};

/// Read the block timestamp from the `Timestamp::Now` storage item at
/// the given block hash. Returns `None` if the pallet is absent or the
/// value is missing (e.g. pre-Timestamp genesis block).
pub(crate) async fn read_block_timestamp(
    client: &OnlineClient<PolkadotConfig>,
    block_hash: subxt::utils::H256,
) -> ChainResult<Option<u64>> {
    let query = subxt::dynamic::storage("Timestamp", "Now", Vec::<scale_value::Value>::new());
    let at_block = client.at(block_hash).await
        .map_err(|e| ChainError::RpcError(e.to_string()))?;

    let raw = at_block.storage().entry(query)
        .map_err(|e| ChainError::RpcError(e.to_string()))?
        .fetch().await
        .map_err(|e| ChainError::RpcError(e.to_string()))?;

    let Some(value) = raw else { return Ok(None) };
    let bytes = value.bytes();

    // Timestamp::Now is Moment = u64 (SCALE-encoded, little-endian, fixed-width)
    let ts = u64::decode(&mut &bytes[..])
        .map_err(|e| ChainError::RpcError(format!("decode Timestamp::Now: {}", e)))?;

    Ok(Some(ts))
}
```

### Integration

`decode::decode_raw_block` takes `&OnlineClient<PolkadotConfig>` as its first argument so it can perform the storage read. The stream wrapper in `impl BlockSource` clones `self.client` and passes it through. No public impact.

### Impact

- ~90 lines of code removed
- 5 unit tests removed (covered the `Compact<u64>` decoder and debug parse)
- `RawBlock.timestamp: Option<u64>` contract unchanged

### Cost consideration

One extra RPC per block for the storage read. At 6s/block (finalized head mode) this is negligible. In Phase 2 (historical sync at high throughput) this may become a hot path; possible future optimizations:
- Parallelize the storage read with `decode_extrinsics` / `decode_events` (already async)
- Fall back to `Compact<u64>` decoding of the `Timestamp.set` extrinsic on storage read failure

Both are **out of scope for Phase 1**.

## 4. SCALE → JSON conversion rewrite

### Context

~150 lines of in-house code in `client.rs` convert `subxt::ext::scale_value::Value<T>` to `serde_json::Value`, used to populate `RawEvent.data` and `RawExtrinsic.args`. Consumers are handlers (`crates/handlers/`) via `extract_field`, `parse_account`, `parse_amount`, `parse_hash256`.

### Contract to preserve (handler JSON invariants)

Derived from inspection of `crates/handlers/src/utils.rs` and handler call sites:

**Core invariants** (violations = silent handler breakage):

1. **Named field names**: `Composite::Named([("from", ...), ("amount", ...)])` → JSON object with the **exact FRAME field names** as keys (this is what `extract_field` searches for via `&["from", "who"]` etc.)
2. **Byte array hex form**: unnamed composites of 20 or 32 primitive `u8`-range values → `"0x…"` hex string (prefix + lowercase, matching `parse_account` / `parse_hash256` first-case)
3. **u128/i128 as decimal strings**: 128-bit primitives → JSON string, not number (`serde_json::Number` does not carry 128-bit precision; `parse_amount` handles both number and string inputs but precision loss at u64 boundary is unacceptable for Balances amounts)

**Additional rules** (from current implementation, same reason — preserving handler behavior):

4. `Variant { name: "Some", values: [v] }` → `v` (Option unwrap); `"None"` → `null`
5. `Variant { name: "Id", values: [v] }` → `v` (`MultiAddress::Id(AccountId)` unwrap)
6. `Composite::Unnamed([v])` (single-element tuple = newtype wrapper) → `v`
7. Other variants → `{"VariantName": <inner>}`
8. `Composite::Unnamed([v1, v2, …])` with >1 element → `[v1, v2, …]` JSON array

### New module: `crates/substrate/src/scale_json.rs`

```rust
//! SCALE Value → JSON conversion preserving the handler JSON contract.
//!
//! Invariants (violations silently break handlers):
//!   (1) Named composites keep FRAME field names verbatim.
//!   (2) 20/32-byte unnamed composites of u8-range primitives serialize
//!       as "0x…" hex strings (lowercase, 0x-prefixed).
//!   (3) u128/i128 primitives serialize as decimal strings (serde_json::Number
//!       does not carry 128-bit precision).
//!   (4) Option::Some/None and MultiAddress::Id variants are unwrapped.
//!   (5) Single-element unnamed composites (newtype wrappers) are unwrapped.

use scale_value::{Composite, Primitive, Value, ValueDef};

pub(crate) fn value_to_json<T>(v: &Value<T>) -> serde_json::Value {
    value_def_to_json(&v.value)
}

fn value_def_to_json<T>(v: &ValueDef<T>) -> serde_json::Value {
    match v {
        ValueDef::Composite(c) => composite_to_json(c),
        ValueDef::Variant(var) => match var.name.as_str() {
            "Some" => unwrap_single(&var.values),
            "None" => serde_json::Value::Null,
            "Id"   => unwrap_single(&var.values),
            other  => {
                let mut m = serde_json::Map::new();
                m.insert(other.to_string(), composite_to_json(&var.values));
                serde_json::Value::Object(m)
            }
        },
        ValueDef::Primitive(p) => primitive_to_json(p),
        ValueDef::BitSequence(b) => serde_json::Value::String(format!("{:?}", b)),
    }
}

pub(crate) fn composite_to_json<T>(c: &Composite<T>) -> serde_json::Value {
    match c {
        Composite::Named(fields) => {
            let map: serde_json::Map<_, _> = fields.iter()
                .map(|(name, v)| (name.clone(), value_to_json(v)))
                .collect();
            serde_json::Value::Object(map)
        }
        Composite::Unnamed(values) => {
            if let Some(hex) = try_as_byte_array(values) {
                return serde_json::Value::String(hex);
            }
            if values.len() == 1 {
                return value_to_json(&values[0]);
            }
            serde_json::Value::Array(values.iter().map(value_to_json).collect())
        }
    }
}

fn unwrap_single<T>(c: &Composite<T>) -> serde_json::Value {
    match c {
        Composite::Unnamed(vs) if vs.len() == 1 => value_to_json(&vs[0]),
        _ => composite_to_json(c),
    }
}

fn try_as_byte_array<T>(values: &[Value<T>]) -> Option<String> {
    let len = values.len();
    if len != 32 && len != 20 { return None; }
    let mut bytes = Vec::with_capacity(len);
    for v in values {
        let ValueDef::Primitive(Primitive::U128(n)) = &v.value else { return None };
        if *n > 255 { return None }
        bytes.push(*n as u8);
    }
    Some(format!("0x{}", hex::encode(bytes)))
}

fn primitive_to_json(p: &Primitive) -> serde_json::Value {
    match p {
        Primitive::Bool(b)   => serde_json::Value::Bool(*b),
        Primitive::Char(c)   => serde_json::Value::String(c.to_string()),
        Primitive::String(s) => serde_json::Value::String(s.clone()),
        Primitive::U128(n)   => serde_json::Value::String(n.to_string()),
        Primitive::I128(n)   => serde_json::Value::String(n.to_string()),
        Primitive::U256(n)   => serde_json::Value::String(format!("{:?}", n)),
        Primitive::I256(n)   => serde_json::Value::String(format!("{:?}", n)),
    }
}
```

### Differences from current implementation

One intentional change: **`len == 64` is removed from the byte-array detector**. No current handler consumes 64-byte arrays, and the risk of false positives (a 64-element unnamed tuple of u8-range values that is not in fact a byte array) outweighs the benefit. If the smoke test reveals a case that depends on this, it will be restored (see R5).

### Where `Value<T>` comes from

Produced by `decode_events` and `decode_extrinsics` via `ev.field_values()` / `ext.field_values()`. If 0.50 changes these signatures or routes through `frame-decode`, the `scale_json` module remains unchanged — only the `decode/` modules absorb the adaptation. See R2.

### `scale-value` dependency sourcing

Currently `subxt::ext::scale_value`. If 0.50 keeps the re-export → nothing to do. If the re-export is removed (consistent with `subxt-core` retirement) → add a direct `scale-value` dependency pinned to match the version used internally by subxt 0.50 (for ABI compatibility). Resolved at first compile.

### Unit tests (in `scale_json.rs`, on synthetic `Value<T>`, no node required)

- `Composite::Named` → `Object` with exact names
- `Composite::Unnamed([32 × U128(0..32)])` → hex string `"0x0001…1f"`
- `Composite::Unnamed([1 × inner])` → `inner` (newtype unwrap)
- `Variant("Some", [inner])` → `inner`
- `Variant("None", [])` → `null`
- `Variant("Id", [account])` → `account`
- `Variant("Other", values)` → `{"Other": …}`
- `U128(u128::MAX)` → `"340282366920938463463374607431768211455"` (no precision loss)
- `Composite::Unnamed([32 × U128(256)])` → **not** a byte array (invariant preserved)

These pin the invariants independently of the real node. Golden fixtures (Section 5) validate the full pipeline.

## 5. Testing strategy

### Fixture (one, for the balances block)

```
crates/substrate/tests/
├── fixtures/
│   ├── README.md                             # how to regenerate
│   ├── balances_block_<num>_<hash8>.json     # metadata: number, hash, expected shape
│   ├── balances_block_<num>_<hash8>.scale    # body SCALE bytes
│   ├── balances_block_<num>_<hash8>_events.scale
│   ├── balances_block_<num>_<hash8>_timestamp.scale  # Timestamp::Now u64 bytes
│   └── metadata_<runtime_version>.scale      # runtime metadata
└── golden_decode.rs                          # the test
```

Rationale for a single fixture (balances only): it exercises the most fragile path — `Composite::Named` → `extract_field` → `parse_account` / `parse_amount` — which is the part of the cleanup most likely to regress silently. ATS and MIDDS are not covered by fixtures in Phase 1; they are validated empirically by the smoke test.

### Capture binary

`crates/substrate/examples/capture_fixture.rs`, run **manually, once**, by the developer against the Allfeat node:

```
cargo run -p maestro-substrate --example capture_fixture -- \
    --ws-url ws://node.allfeat.io:9944 \
    --block-hash 0x...abc \
    --out crates/substrate/tests/fixtures/
```

Never executed in CI. Exists only to make regeneration reproducible.

### The test

`crates/substrate/tests/golden_decode.rs`:

```rust
#[test]
fn golden_balances_block_decodes_to_expected_shape() {
    let fx = FixtureDir::load("balances_block_…");
    let raw = decode_block_from_fixture(&fx).expect("decode");

    assert_eq!(raw.number, /* pinned */);
    assert_eq!(raw.timestamp, Some(/* pinned */));
    let transfer = raw.events.iter().find(|e| e.pallet == "Balances" && e.name == "Transfer").unwrap();
    // Invariant (2): byte-array → hex string with 0x prefix
    assert!(transfer.data.get("from").and_then(|v| v.as_str()).unwrap().starts_with("0x"));
    assert!(transfer.data.get("to").and_then(|v| v.as_str()).unwrap().starts_with("0x"));
    // Invariant (3): u128 as decimal string, parseable back to u128
    assert!(transfer.data.get("amount").and_then(|v| v.as_str())
        .unwrap().parse::<u128>().is_ok());
}
```

### Offline-testable decoders

For the fixture test to run without a running node, `decode_events` and `decode_extrinsics` must be callable from `(bytes, metadata)` rather than only from a live `Block<_, _>`. This is a structural consequence of the refactor (noted in R3): the module boundary in `decode/` takes `(body_bytes, events_bytes, metadata, …)` at its test-exposed entry point. The `impl BlockSource` path extracts these from subxt and delegates.

A `pub(crate) mod testing` gated by `#[cfg(any(test, feature = "testing"))]` exposes `FixtureDir` and `decode_block_from_fixture` to the integration test without polluting the release public surface.

### MIDDS storage read

The MIDDS bundle uses `StorageReader::read_storage_map_u64`. This path **is not testable offline** without capturing block state as well. In Phase 1 it is covered only by:
- Unit test on the `storage_query` builder in `storage.rs`
- Manual smoke test (gate criteria 4–5)

### Gate

Repeated from the top of the spec for emphasis:

1. `cargo build --release` passes
2. `cargo clippy --all -- -D warnings` passes
3. `cargo test` passes
4. Manual smoke test: ≥10 blocks indexed against a live Allfeat node, no errors

## 6. Error handling

Phase 1 does **not** take advantage of subxt 0.50's error differentiation. All errors continue to collapse to `subxt::Error` then to `ChainError::*` with the same granularity as today. Rationale: differentiation benefits no upstream consumer in the current codebase, and using it would require touching `maestro-core::error::ChainError`, which is out of scope.

### Concrete mapping (form unchanged)

```rust
// Connection / RPC
.map_err(|e: subxt::Error| ChainError::ConnectionFailed(e.to_string()))

// Block fetch / events / extrinsics / storage
.map_err(|e: subxt::Error| ChainError::RpcError(e.to_string()))

// Stream errors
.map_err(|e: subxt::Error| ChainError::SubscriptionError(e.to_string()))
```

If a 0.50 API returns a specialized error type, pass through `?` or `.into::<subxt::Error>()` before the `.map_err`. One line per call site.

### Per-event decode tolerance (preserved)

`decode_events` currently skips events it cannot decode, emits `trace!` and increments a metric counter:

```rust
for (index, event) in events.iter().enumerate() {
    match event {
        Ok(ev) => { /* decode */ },
        Err(e) => {
            trace!(index, error = ?e, "Failed to decode event");
            record_decode_error("event", "unknown");
        }
    }
}
```

Kept as-is structurally. If 0.50 changes the iterator's item type, the match structure remains identical.

### `ChainError` unchanged

No new variants. `maestro-core/src/error.rs` is not touched.

### Logs unchanged

`tracing::warn!`, `tracing::trace!`, `tracing::error!` at the same call sites, same levels, same field names.

## 7. Risks & open questions

Captured here for the implementation plan (writing-plans, next step). None of these block the start of implementation.

### R1 — Exact 0.50 API symbol names

Four symbols to confirm at first `cargo build`:
- `OnlineClient` constructor that accepts both a `config` and a custom backend
- Stream item type from `stream_blocks()` and how to obtain `events()` / `extrinsics()` / `header()` on it
- Canonical method for raw storage fetch (`storage().fetch_raw(key)` direct vs `storage().entry(query).fetch()`)
- Presence of `subxt::ext::scale_value` re-export

**Fallback**: adjust the affected file (≤5 lines per symbol). No impact on overall design shape.

### R2 — `field_values()` on events/extrinsics in 0.50

`decode_events` / `decode_extrinsics` rely on `ev.field_values()` and `ext.field_values()` returning a `Composite<T>`. If 0.50 migrates them to `frame-decode` with a different shape, the pipeline becomes `frame-decode output → scale_value::Value → scale_json::*`. The `scale_json.rs` module is unchanged (input type stays `Value<T>`). **Cost**: an adaptation layer in `decode/events.rs` and `decode/extrinsics.rs`, ~10–20 lines.

### R3 — `(bytes, metadata) -> …` decoder signatures

Section 5 assumes decoders are offline-testable via `(bytes, metadata)` entry points. If the 0.50 block yield type already exposes sufficient access, this is direct. Otherwise, `client.rs` extracts bytes+metadata once and passes them through. Not a blocker; a choice to make at implementation time.

### R4 — Silent handler contract invariant

The handler JSON invariants (Section 4) come from static inspection of `crates/handlers/src/utils.rs` and call sites. A small probability remains that a handler depends on a detail not captured. The smoke test (gate points 4–5) is the empirical check: if a bundle is empty after smoke, an invariant is missing.

**Mitigation**: invariants documented at the top of `scale_json.rs`; one unit test per invariant so future regressions are caught early.

### R5 — `len == 64` byte array detection

Section 4 removes 64-byte tuple detection. Risk: a current FRAME event yielding a 64-element unnamed tuple of u8-range values would shift from hex string to JSON array.

**Mitigation**: if the smoke test reveals such a case, restore `64` in `try_as_byte_array`. Empirical decision, not a design blocker.

### R6 — Cost of per-block Timestamp storage read

Section 3 adds one RPC per block. Negligible at 6s/block finalized. In Phase 2 (historical sync throughput) may become a point of optimization.

### R7 — Phase 2 hooks to preserve

Three hooks Phase 2 depends on:
- `use_historic_types(false)` flip point in `client.rs`
- `decode::decode_raw_block(client, block)` factored to accept arbitrary blocks
- `BlockSource` trait: Phase 2 will add `fetch_block_at(number_or_hash) -> ChainResult<RawBlock>`, no other changes planned
