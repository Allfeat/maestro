# subxt 0.50 idiomatic-usage refactor

**Status:** draft
**Date:** 2026-04-13
**Scope:** `crates/substrate` only
**Depends on:** `feat(substrate)!: upgrade to subxt 0.50 with decode module split` (commit 48653dc)

## 1. Goal

Post-migration to subxt 0.50, align `crates/substrate` with the usage patterns shown in the upstream reference examples at
`https://github.com/paritytech/subxt/tree/master/subxt/examples`. Remove code that re-implements subxt APIs manually, collapse ceremony
that is no longer required by the framework, and unify the dynamic-decode target on `subxt::dynamic::Value` — the type the examples
use consistently for event and extrinsic decoding.

The refactor is a **cleanup**, not a behavior change: the `BlockSource` and `StorageReader` port contracts are preserved verbatim,
the handler JSON shape contract is preserved verbatim, and the single PR that delivers this work is guarded by existing regression tests.

## 2. Non-goals

- No changes to `maestro-core` (ports, models, errors).
- No changes to `maestro-handlers` — the `StorageReader` port still returns raw SCALE bytes, handlers keep decoding with
  `parity-scale-codec::Decode`.
- No changes to `maestro-graphql`, `maestro-storage`, or the binary.
- No file-structure consolidation (that was Variant 2 in brainstorming; rejected as cleanup creep).
- No `OnlineClient` wrapper newtype (Variant 3; rejected as premature abstraction).
- No reintroduction of the `use_historic_types(false)` chain config hook — Phase 2 (historical block sync) will re-add it when it
  actually flips to `true`.

## 3. Reference examples

The canonical patterns this refactor adopts are drawn from these files in the subxt repo. Every change in §4 points back to one.

| File | What it establishes |
|---|---|
| `subxt/examples/blocks.rs` | Finalized-block streaming: `api.stream_blocks()` → `block.at()` → `at_block.extrinsics().fetch()`. |
| `subxt/examples/historic_blocks.rs` | Dynamic event/extrinsic decode target: `::<Value>()`, not `::<Composite<()>>()`. |
| `subxt/examples/dynamic.rs` | Canonical dynamic storage: `dynamic::storage::<Keys, ValueType>("Pallet", "Item")` → `.fetch(addr, keys).await?.decode()?`. Example includes `Timestamp::Now` verbatim. |
| `subxt/examples/storage_entries.rs` | High-level storage fetch shape, including `.bytes()` access for raw-byte paths. |
| `subxt/examples/rpc_client.rs` | Production RPC client setup: `ReconnectingRpcClient::builder().build(url)` → `RpcClient::new` → `OnlineClient::from_rpc_client`. |

## 4. Design

### 4.1 Architecture & module layout

No structural change. Same files, same public surface:

```
crates/substrate/src/
├── lib.rs              (unchanged)
├── client.rs           (connect/stream rewritten)
├── storage.rs          (storage methods rewritten)
├── scale_json.rs       (unchanged — generic-T entry point re-used)
└── decode/
    ├── mod.rs          (unchanged)
    ├── events.rs       (decode target swap)
    ├── extrinsics.rs   (decode target swap)
    └── timestamp.rs    (collapsed to canonical dynamic-storage fetch)
```

`maestro-core` and `maestro-handlers` are untouched.

### 4.2 `client.rs`

**Current state.** Manually builds a `ChainHeadBackend` via `ChainHeadBackendBuilder::default().build_with_background_driver(rpc_client.clone())`,
then passes an `Arc<backend>` to `OnlineClient::from_backend_with_config` together with a custom
`PolkadotConfig::builder().use_historic_types(false).build()`. Branches the RPC client on URL scheme (`ws://` → `from_insecure_url`,
`wss://` → `from_url`).

**New state.** Follow `rpc_client.rs` verbatim. Single code path:

```rust
let inner = ReconnectingRpcClient::builder()
    .build(&config.ws_url)
    .await
    .map_err(|e| ChainError::ConnectionFailed(e.to_string()))?;
let rpc_client = RpcClient::new(inner);
let client = OnlineClient::<PolkadotConfig>::from_rpc_client(rpc_client).await
    .map_err(|e| ChainError::ConnectionFailed(e.to_string()))?;
```

**Removed:**
- `ChainHeadBackendBuilder`, `from_backend_with_config`, `Arc::new(backend)`.
- The `PolkadotConfig::builder().use_historic_types(false).build()` hook (dead code until Phase 2).
- The `ws://` vs `wss://` scheme branch in RPC-client construction.
- The pre-0.50 historical comments on `finalized_head` and `best_head` explaining the old `at_latest` quirk.

**Preserved unchanged:**
- `current_head`, `finalized_head`, `best_head`, `runtime_version` bodies (they already call `at_current_block()` and
  read `block_number` / `block_hash` / `spec_version`, which match the examples).
- `subscribe_finalized` → `stream_blocks()`, `subscribe_best` → `stream_best_blocks()`. Already canonical.

**Research item during implementation (R1).** Confirm that `ReconnectingRpcClient::builder().build(url)` accepts `ws://` URLs without
requiring a separate insecure toggle. If it does not, fall back to using `ReconnectingRpcClient` only for `wss://` and a
non-reconnecting `RpcClient::from_insecure_url` for `ws://`, with a TODO tying the resolution to upstream support. The fallback
preserves the current behavior exactly.

### 4.3 `decode/mod.rs`

No functional change. `decode_raw_block` still fetches events once up front and shares the handle between
`decode_events` and `decode_extrinsics`. The event-fetch optimization (one RPC, two consumers) is retained and is an intentional
deviation from `blocks.rs`, which fetches per-extrinsic events.

### 4.4 `decode/extrinsics.rs`

**Change.** Swap the dynamic-decode target:

```rust
// Before
ext.decode_call_data_fields_unchecked_as::<Composite<()>>()
    .map(|composite| composite_to_json(&composite))

// After  (matches historic_blocks.rs line: `decode_call_data_fields_unchecked_as::<Value>()?`)
ext.decode_call_data_fields_unchecked_as::<subxt::dynamic::Value>()
    .map(|value| value_to_json(&value))
```

**Removed imports:** `subxt::ext::scale_value::Composite`.
**Added imports:** `subxt::dynamic::Value` (type alias for `scale_value::Value<u32>`).

Everything else in the function is unchanged: the `extrinsics.iter().enumerate()` loop, `ext.pallet_name()` / `ext.call_name()`,
`ext.address_bytes()`, the `build_extrinsic_results` lookup for `(success, error)`, the trace/metric on decode failure.

### 4.5 `decode/events.rs`

Same decode-target swap, in two places:

1. `decode_events`: `ev.decode_fields_unchecked_as::<Composite<()>>()` → `::<Value>()`, with `composite_to_json` → `value_to_json`.
2. `build_extrinsic_results` (`ExtrinsicFailed` branch): same swap. The subsequent `format!("{:?}", v)` used for the error string
   works identically on `Value` and `Composite<()>` (both implement `Debug`).

**Removed imports:** `subxt::ext::scale_value::Composite`.

### 4.6 `decode/timestamp.rs`

**Current state.** 55 lines. Constructs a `subxt::dynamic::storage::<Vec<subxt::dynamic::Value>, subxt::dynamic::Value>` query,
calls `at_block.storage().entry(query)?.try_fetch(vec![]).await`, then manually decodes the raw bytes with `u64::decode(&mut &bytes[..])`.

**New state.** The canonical `dynamic.rs` pattern:

```rust
use subxt::dynamic;
use maestro_core::error::{ChainError, ChainResult};
use crate::client::SubstrateClientAtBlock;

pub(crate) async fn read_block_timestamp(
    at_block: &SubstrateClientAtBlock,
) -> ChainResult<Option<u64>> {
    let addr = dynamic::storage::<(), u64>("Timestamp", "Now");
    let value = at_block
        .storage()
        .fetch(addr, ())
        .await
        .map_err(|e| ChainError::RpcError(format!("fetch Timestamp::Now: {}", e)))?;
    match value {
        Some(v) => Ok(Some(
            v.decode()
                .map_err(|e| ChainError::RpcError(format!("decode Timestamp::Now: {}", e)))?,
        )),
        None => Ok(None),
    }
}
```

**Removed:**
- `codec::Decode` import and the manual `u64::decode(&mut &raw_bytes[..])` path.
- The `entry()` construction `Err` branch that logged "Timestamp pallet absent" and returned `Ok(None)`. Under the new path, a
  missing metadata entry surfaces as an `Err` from `fetch`, mapped to `ChainError::RpcError`. Rationale: a runtime without
  `Timestamp::Now` is an exceptional indexer-operator mistake, not a per-block soft-failure; surfacing it as a loud error is
  more correct than silently writing `NULL` timestamps for every block.
- The `dynamic_storage_query_for_timestamp_now_compiles` reachability test — it guarded the `entry + try_fetch` shape which no
  longer exists. The new shape's reachability is enforced at compile time by the `dynamic::storage::<(), u64>` type parameters.

### 4.7 `storage.rs`

The `StorageReader` port returns `Option<Vec<u8>>` — **raw SCALE bytes**, consumed by handlers via `parity-scale-codec::Decode`.
This contract is load-bearing (see `crates/handlers/src/midds/handler.rs` lines 53–72 and adjacent) and **must not change**.

**Current state.** Uses the low-level shape `at_block.storage().entry(query)?.try_fetch(keys).await`, with keys built as
`vec![subxt::dynamic::Value::u128(key as u128)]` or `vec![subxt::dynamic::Value::from_bytes(map_key)]`, then reads
`value.bytes().to_vec()`.

**New state.** Use the high-level idiomatic shape from `storage_entries.rs` / `dynamic.rs`:

```rust
// read_storage_map_u64
let addr = dynamic::storage::<(u128,), Value>(pallet, item);
let value = at_block
    .storage()
    .fetch(addr, (key as u128,))
    .await
    .map_err(|e| ChainError::RpcError(format!("Failed to fetch storage: {}", e)))?;
Ok(value.map(|v| v.bytes().to_vec()))
```

For `read_storage_map` (byte-key variant), the typed key tuple is `(Vec<u8>,)`:

```rust
let addr = dynamic::storage::<(Vec<u8>,), Value>(pallet, item);
let value = at_block
    .storage()
    .fetch(addr, (map_key.to_vec(),))
    .await
    .map_err(|e| ChainError::RpcError(format!("Failed to fetch storage: {}", e)))?;
Ok(value.map(|v| v.bytes().to_vec()))
```

`read_storage` (raw-key path) keeps its existing `at_block.storage().fetch_raw(key.to_vec()).await` + `optional_fetch_raw` helper.
That is already canonical for the raw-key case (no pallet/item name to feed into `dynamic::storage`), and there is no higher-level
equivalent.

**Regression guard (new test, R2).** Add a pure compile-and-encode unit test that constructs the `dynamic::storage::<(u128,), _>`
address for a pallet/item pair present in the runtime metadata fixture used by the existing golden-decoder test, and asserts that
the **encoded storage key bytes** match the result of the current `Value::u128(...)` path for a fixed input. The test runs offline,
no RPC required. It is the guard against subxt silently changing the hasher-key encoding semantics between the typed-tuple and
`Value`-dynamic code paths.

**Fallback (R3).** If the regression guard in R2 shows a mismatch between `(u128,)` and `Value::u128(...)` encoding (or `(Vec<u8>,)`
and `Value::from_bytes(...)`), revert that specific method to pass a single-element tuple of `Value` instead of a typed tuple:
`dynamic::storage::<(Value,), Value>(pallet, item)` + `.fetch(addr, (Value::u128(key as u128),))`. This preserves exact byte-for-byte
behavior while still moving off the `entry + try_fetch` shape. Document in the code comment which call sites use this fallback and why.

**Removed test:** `dynamic_storage_map_builder_constructs_for_known_pallet` — it guarded the `entry` construction shape.

### 4.8 `scale_json.rs`

**Zero code change in the converter itself.** `value_to_json<T>`, `composite_to_json<T>`, `value_def_to_json<T>`,
`primitive_to_json`, and `try_as_byte_array<T>` are already generic over the `Value` / `Composite` type parameter `T`. Decoding into
`subxt::dynamic::Value = scale_value::Value<u32>` exercises the exact same code paths as the existing tests, which use
`Value<()>` / `Composite<()>`.

The only edit is a one-line update to the file docstring stating that the decoder now feeds `Value` directly rather than
`Composite`, so future readers do not wonder why the public API is generic-T yet all call sites instantiate the same `T`.

**Tests unchanged.** All 14 existing `scale_json.rs` unit tests run verbatim and are the primary guard of the handler JSON shape
contract. If any fail, the decoder unification broke an invariant.

## 5. Error handling

No new error types or variants. All subxt errors continue to funnel through:

- `ChainError::ConnectionFailed(e.to_string())` — RPC/client construction in `client.rs`.
- `ChainError::SubscriptionError(e.to_string())` — stream setup and per-block errors in `subscribe_finalized` / `subscribe_best`.
- `ChainError::RpcError(e.to_string())` — everything else, including the new `timestamp.rs` and `storage.rs` code paths.

Two small adjustments:

1. `timestamp.rs`: both the `fetch` error and the `decode` error map to `ChainError::RpcError`. A decode failure on `Timestamp::Now`
   means the metadata and the on-chain value disagree on the `u64` shape, which is an RPC-path anomaly, not a domain error. The
   explicit `Ok(None)` branch for a missing pallet (previously from the `entry()` `Err`) is removed — a runtime without `Timestamp`
   is an operator mistake and surfaces through the normal error path.
2. `storage.rs`: the `StorageError::NoValueFound → Ok(None)` special case in `read_storage` is preserved via the existing
   `optional_fetch_raw` helper (raw-key path is unchanged). For the `read_storage_map` / `read_storage_map_u64` methods, the new
   `.fetch(addr, keys)` returns `Option<_>` natively, so the `NoValueFound` special case collapses into the `Ok(value.map(...))`
   expression — no helper needed.

## 6. Testing

Four regression layers, cheapest first:

1. **`cargo clippy --all -- -D warnings`.** Catches the `Composite` → `Value` type-parameter drift, unused imports from the removed
   paths, and any fallout from the removed dead code. Run after each file rewrite.
2. **Existing `scale_json.rs` unit tests (14 tests).** Cover named and unnamed composites, the 20- and 32-byte hex detector, the
   regression guard for 64-byte tuples (spec §4 R5 from the upgrade plan), the u128 decimal-string contract, `Option::Some`/`None`
   unwrapping, `MultiAddress::Id` unwrapping, single-element newtype unwrapping, and variants with named payloads. These are the
   primary handler-JSON-contract guard. Any failure means the decoder unification broke an invariant.
3. **New `storage.rs` key-encoding test (R2 from §4.7).** Offline compile-and-encode assertion that the new typed-tuple key path
   produces byte-identical storage keys to the current `Value::u128(...)` / `Value::from_bytes(...)` path for a fixed input. Guards
   the switch from dynamic-value keys to static-type keys.
4. **Existing Phase 1 golden decoder test** (`decode_block_from_fixture`, Task 13 of the 2026-04-13-subxt-0.50-upgrade plan).
   Offline end-to-end test: loads a committed fixture of a real block's decoded bytes, runs it through the full decode pipeline,
   and asserts the resulting JSON matches the committed golden output. Any drift in the handler JSON shape surfaces here. Runs
   without a live node.

**Removed tests:**

- `dynamic_storage_query_for_timestamp_now_compiles` (`timestamp.rs`) — guarded the removed `entry + try_fetch` shape.
- `dynamic_storage_map_builder_constructs_for_known_pallet` (`storage.rs`) — same reason.

**Manual smoke (one-time).** After the workspace gate (`cargo build --all && cargo test --all && cargo clippy --all -- -D warnings`)
passes, one `cargo run --bin maestro` against a live dev node, observe 5+ finalized blocks stream and persist, spot-check one block's
extrinsics/events/timestamp rows in Postgres against pre-refactor output. Documented in the implementation plan as a manual step.

## 7. Rollout

- Single PR on a feature branch off `develop`.
- No feature flag, no staged rollout. The four regression layers in §6 are sufficient gates.
- If the golden decoder test drifts, the PR is blocked until the drift is understood: either a bug in the refactor, or a
  legitimate improvement that requires regenerating the fixture with a documented rationale in the commit message.
- Single squash-merge commit message: `refactor(substrate): align with subxt 0.50 idiomatic usage`. Body references this spec and
  the five reference example files from §3.

## 8. Phase 2 hooks preserved

The Phase 2 design (`docs/superpowers/plans/` entry for historical block sync) depends on:

- `OnlineClient::at_block(block_number)` — preserved, used identically in `storage.rs` today.
- `PolkadotConfig::builder().use_historic_types(true)` — **removed** by this refactor. Phase 2 reintroduces it when it actually
  flips to `true`, at which point the `ChainHeadBackendBuilder + from_backend_with_config` wiring returns (with a one-line comment
  explaining why we need the non-default config). This refactor does not pretend to preserve dead code for a hook that no current
  code path uses.
- The golden decoder test fixture — preserved, and acts as the contract guard across both this refactor and Phase 2.

## 9. Acceptance criteria

1. `client.rs` contains no reference to `ChainHeadBackendBuilder`, `from_backend_with_config`, `use_historic_types`, or the
   `ws://` / `wss://` scheme branch.
2. `client.rs` uses `ReconnectingRpcClient::builder().build(url)` + `RpcClient::new` + `OnlineClient::from_rpc_client` (or the R1
   fallback if upstream does not accept `ws://`).
3. `decode/extrinsics.rs` and `decode/events.rs` decode into `subxt::dynamic::Value` and call `value_to_json`, with no remaining
   references to `Composite<()>` as a decode target.
4. `decode/timestamp.rs` is at most 25 lines and uses `dynamic::storage::<(), u64>("Timestamp", "Now")` + `.fetch(addr, ())` +
   `.decode()`.
5. `storage.rs` uses `at_block.storage().fetch(addr, keys)` for the dynamic-storage paths (not `entry + try_fetch`); the raw-key
   path continues to use `fetch_raw`.
6. `scale_json.rs` converter code is unchanged (docstring update only).
7. `cargo build --all && cargo test --all && cargo clippy --all -- -D warnings` passes.
8. The `scale_json.rs` unit tests and the Phase 1 golden decoder test both pass unchanged.
9. The new `storage.rs` key-encoding regression test passes.
10. One manual smoke run against a live dev node processes at least 5 finalized blocks with no divergence from pre-refactor output.
